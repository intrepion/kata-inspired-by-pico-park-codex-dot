# Together, Little Lights
Original six-stage garden puzzle-platformer. Default local keyboard co-op: Sol uses A/D/W/E; Luna uses arrows/Up/Enter. Solo: A/D/W/E or arrows/Up/Enter control selected creature, Tab swaps; the unselected creature receives no movement input and may ride a moving friend. No online multiplayer.

Acceptance: fixed 120Hz simulation, reliable solid collision, buffered/coyote jump, role-specific persistent beacons, shared retained key, portal requiring both creatures and all beacons, complete fresh restart, immediate fall recovery, six distinct puzzles, accessible DOM start/pause/select/completion, validated local progress, mute/reduced motion, touch solo controls, no inputs through menus. No commercial art/audio/layout copying. Type checks, tests, production build, audit, normal-control campaign/browser verification, private repo push and CI.

Public test seams authorized by the delegated request: createWorld/step for physics and puzzle state; decodeProgress for untrusted saves. TDD proceeds one behavior slice at a time. Rendering stays separate from simulation. The original decision to omit player stacking is superseded by the approved fidelity fix below.

No-interview adaptation: the user explicitly delegated recommended decisions and asked for no design questions. Local grilling's confirmation/interview and TDD seam-confirmation steps are fulfilled by this authorization. Decision tree: local game → simultaneous keyboard + solo parked character → persistent role beacons → shared key → both at portal; original garden theme → six short increasingly layered routes; browser TypeScript → independent fixed simulation → Canvas scene + DOM controls.

Review refinement: Garden five uses a movable planter constrained to a shelf rail. It must be pushed right and climbed to reach the raised sun beacon; Luna opens the route first. The rail avoids gravity/crate-reset softlocks, and another creature blocks pushing rather than being crushed. Input-buffer and TickClock public seams were added in response to browser findings and frame-scheduling verification under the original test authorization.

## Approved stacking fidelity fix · 2026-10-14

Friends have solid sides, heads and feet. A falling friend can stand on the other; a base carries its rider with actual horizontal and vertical movement. The rider retains independent movement/jump, jump buffering and coyote time. A rider's wall or ceiling contact limits the base's movement, preventing crush and terrain penetration. Upward head collisions stop ascent; high-speed falling does not tunnel through friends. An occupied recovery spawn uses a nearby free position. Fixed 120Hz physics, local co-op, solo switching, six existing layouts and version-1 saves remain valid. No forced teammate side pushing, additional cooperative gimmicks, new campaign stages, networking or asset rewrite is included.

The user authorized test-driven implementation and recommended defaults at existing public seams. The design choices and concrete scenarios are recorded in ADR 0002, without another optional interview. Browser verification must use normal input and observed stacking/carry/jump responses; source tests or dispatched keys alone are not browser evidence.
